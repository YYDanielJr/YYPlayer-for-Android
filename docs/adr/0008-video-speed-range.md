# ADR0008：视频倍速范围（U20 统一 0.1×–8×）

## 当前决定：U20，2026-10-14

用户主动将上限降至 8×，以移除特殊适配。UI 和两个后端统一 0.1×–8×／步进 0.1×；快捷 0.5／1／1.25／1.5／2／3 保留。移除 `setVideoSpeed` 的后端自动切换包装及引擎切换的 requestedSpeed 参数，UI 直接调用原有 `setSpeed`；滑杆不再接收后端和严格硬解状态。仅硬解无需单独上限，解码能力与限制保持原状。

这样遵守两个后端共有范围，调倍速不改变后端选择，越界请求统一限制到 8。3× 临时覆盖恢复基础速度（含 0.1／8）；验证见 [U20](../validation/video-u20/README.md)。

## 历史：U19 的 10× 决定（已被上文覆盖）


日期：2026-10-14。用户要求设置内按 0.1× 调节 0.1×–10×，外侧快捷档位不变。

## 事实与候选

锁定 Media3 1.11.1 的 `DefaultAudioSink.setPlaybackParameters` 在软件音频变速路径将 speed 限制为 0.1–8（本地 AAR 的 classes.jar 经 javap 核实）。当前输出明确关闭 AudioTrack playback params。只把 UI 和 PlaybackParameters 上限改成 10 会导致实际音频时钟回落，不能称为真实 10×。

候选：修改／重写音频变速管线；请求平台 AudioTrack 变速但依赖设备能力；使用 U16 已有 libmpv。选择现有 libmpv，避免自写时钟／音频处理和改变音乐输出。

## 决定与影响

- 新入口「播放工具 → 播放倍速」，滑杆松手生效、加减 0.1×、一键恢复 1×，范围 0.1–10。快捷选择仍为 0.5／1／1.25／1.5／2／3，1.25 不被全局量化。
- 默认 Media3 支持 0.1–8；自由调节超过 8 时通过既有后端切换流程进入 libmpv，界面提前说明。保持位置、播放意图和音量；切换后的后端选择按现有偏好保存，不因降速自动切回。手动回到 Media3 时当前速度限制为 8。
- Media3 仅硬解模式保留最高 8×，界面说明需先改变解码策略，不为更高倍速静默放弃严格硬解。
- libmpv 支持全范围；音乐原有快捷选项和 native 精确输出拒绝变速规则不变。长按仍是绝对 3×，松手恢复原基础速度，包括 0.1× 和 10×。
- 此路由不表示原生默认全面迁移完成；U16 的供应链、实体设备和 HDR 资格限制继续有效。

## 验证

以 U19 验证记录为准：UI 实际拖动／无障碍设置／加减／原快捷档位，真实 mpv speed 属性、重建、3× 恢复与既有回归。MuMu 不代替物理设备高速解码、帧率和听感验证。
